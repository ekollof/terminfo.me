## مشارکت با یک ورودی terminfo جدید

ما از فایل‌های منبع terminfo با کیفیت بالا برای ترمینال‌هایی که در پایگاه داده ncurses سیستم وجود ندارند یا تعاریف بهتر/کامل‌تری دارند، استقبال می‌کنیم.

**نکته زبان:** لطفاً توضیحات issueها، pull requestها و نظرات را به زبان انگلیسی بنویسید. این کار به نگهدارندگان کمک می‌کند تا مشارکت‌ها را کارآمدتر بررسی کنند.

### شروع سریع (توصیه‌شده)

ساده‌ترین راه برای مشارکت، **ابتدا باز کردن یک issue** است:

→ **[ارسال terminfo جدید از طریق Issue گیت‌هاب](https://github.com/ekollof/terminfo.me/issues/new?template=new-terminfo.yml)**

این به ما فرصت می‌دهد ورودی را بررسی کنیم و قبل از باز کردن pull request بازخورد بدهیم.

---

### فرآیند دستی (برای مشارکت‌کنندگان با تجربه)

اگر ترجیح می‌دهید مستقیماً یک PR باز کنید، این مراحل را دنبال کنید:

#### 1. فایل `.ti` را ایجاد کنید

یک فایل جدید در `static/terminfo/<نام-ترمینال>.ti` با این فرمت سرآیند ایجاد کنید:

```text
# -----------------------------------------------------------------------------
# Terminal: <نام-ترمینال>
# Source:   <آدرس منبع رسمی یا مستندات>
# License:  <مثلاً MIT, Public Domain, GPL-2.0>
# Notes:    <هر قابلیت خاص یا نکته>
# -----------------------------------------------------------------------------
```

مثال:

```text
# -----------------------------------------------------------------------------
# Terminal: ghostty
# Source:   https://github.com/ghostty-org/ghostty
# License:  MIT
# Notes:    شبیه‌ساز ترمینال Ghostty (2025+)
# -----------------------------------------------------------------------------
ghostty|Ghostty terminal emulator,
    ...
```

#### 2. فایل را به صورت محلی اعتبارسنجی کنید

```bash
# بررسی نحو
tic -x static/terminfo/terminal-شما.ti

# اجرای مجموعه کامل اعتبارسنجی‌ها
contrib/run-all-checks.sh
```

#### 3. جمع‌های کنترل را به‌روزرسانی کنید

```bash
sha256sum static/terminfo/terminal-شما.ti >> static/terminfo/checksums.txt
```

یا اجازه دهید pre-commit hook این کار را برای شما انجام دهد (توصیه‌شده):

```bash
# راه‌اندازی یک‌باره
cp contrib/pre-commit .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

#### 4. یک Pull Request باز کنید

- یک برنچ ایجاد کنید: `git checkout -b add-ترمینال-شما`
- تغییرات خود را commit کنید (pre-commit hook کمک خواهد کرد)
- یک PR با توضیح واضح باز کنید

---

### چه چیزی یک مشارکت خوب می‌سازد؟

- ورودی **باید** به طور تمیز با `tic -x` کامپایل شود
- ورودی‌هایی که **معتبر** هستند (از خود پروژه ترمینال) را ترجیح دهید
- تا حد امکان قابلیت‌های مدرن را شامل کنید (`XT`, `Tc`, `Su`, پروتکل صفحه‌کلید kitty و غیره)
- منبع را به طور واضح در سرآیند مستند کنید

### آیین‌نامه رفتاری

محترمانه و سازنده باشید. شبیه‌سازهای ترمینال به سرعت تکامل می‌یابند — همه ما در تلاش هستیم زندگی با ترمینال‌های راه‌دور را برای همه بهتر کنیم.

سؤال؟ یک issue باز کنید یا در PR به ما اشاره کنید.
